Technical questions

QuestionOne-line answer
What is drift-checked?Generated .py has spec_hash header. CI re-renders from YAML; fails if file ≠ spec. → Slide 5 here for example.
What’s in YAML specs?Human: source, transforms, quality, compute. Machine: config/codegen/*.spec.yaml. Show folder in Live Part 1 (slide 9).
Who approves?Discovery: human answers before codegen. Deploy: explicit “I approve deploy” before AWS changes.
Why Iceberg?ACID on S3, time travel, Glue catalog. Silver/Gold writes need Spark (glueetl).
Quality gates 0.80 / 0.95?Silver ≥ 0.80, Gold ≥ 0.95 before SFN continues. Rule scores from quality_rules.yaml, not checksums.
Agent autonomous?No — HITL discovery, deploy gate, write guard blocks direct edits to generated scripts.
Spec wrong?pytest + drift + validators locally; gates catch bad data. Wrong business rules still need human discovery.
MCP vs Terraform?MCP: catalog, LF, metadata. Terraform: Glue jobs, Lambda, Step Functions. Jobs always TF in Track A.
Why hybrid MCP?Cursor local; Gateway for cloud deploy tools. Operations layer only — Glue runs in AWS after deploy.
Real or toy data?supplier_lead_times = factory acceptance SKU, real CSV pattern, catalog-only Gold, low cost.

MCP vs Terraform — likely questions

QuestionOne-line answer
Why two tools?MCP = agent catalog/LF/metadata tools. TF = Glue jobs, SFN, Lambda — no MCP create for those in Track A. One owner per ARN.
Does MCP create Glue jobs?No. MCP creates database/tables. Terraform creates job definitions that point at synced scripts.
What runs first?Validate/drift → sync scripts to S3 → MCP catalog/LF → you APPROVE → terraform apply → SFN.
Can we use Terraform only?Yes — set owner: terraform in compute.yaml for a slice; must match generated .tf (CI checks).
Who owns IAM/KMS?Default MCP in factory SKUs; declared in compute.yaml. Client may flip to TF for enterprise module fit.
Is this production IaC?Pattern + generated modules; client maps to their TF pipelines and approval gates.
What if MCP fails?Phase 0 health check before deploy; fix Gateway/profile — don’t apply TF with half catalog.
vs our existing Terraform?Same runtime assets — factory generates workloads_*.tf module; you merge into existing root module.

Say: “Metadata via MCP agents; compute via Terraform — declared in compute.yaml, not ad hoc.”

Hybrid MCP / Gateway — likely questions

QuestionOne-line answer
Is MCP the pipeline?No. MCP = agent tool bus (Operations). Pipeline = Glue + SFN in AWS (Slide 4).
Does data run on my laptop?No. Hybrid only changes how Cursor calls deploy tools. Bronze→Gold runs in AWS after deploy.
local vs hybrid vs gateway?local = all stdio on laptop. hybrid = Gateway + some local (demo default). gateway = all cloud MCP.
Why hybrid for demo?Cloud glue-athena/LF without running 13 local processes; still laptop-led story.
What is AgentCore Gateway?AWS-hosted MCP endpoint — Lambda targets behind one Gateway URL (via stdio proxy in Cursor).
Slide 6 vs Slide 7?Slide 6 = what MCP creates. Slide 7 = how Cursor connects to MCP.
Gateway error in Cursor?Use stdio proxy: switch_mcp_mode.py --mode gateway --aws-profile aws-agent, Reload Window, verify_gateway_mcp.py.
Can we skip Gateway?Yes — local mode + Part 1 works; deploy still uses MCP stdio or TF per compute.yaml.
