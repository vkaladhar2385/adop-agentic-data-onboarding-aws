The problem

Onboarding one governed feed is still a two-week project

  • Hand-written PySpark for Bronze → Silver → Gold
  • Quality rules authored column by column
  • Orchestration, IaC, PII, KMS zoning, Lake Formation tags redone every time
  • Defects found in production, not in review
  • Governance quality varies by who built the last feed

At dozens of sources a year, that is months of senior engineer time — and inconsistent controls.

What changes

Describe the source. Review generated, tested artifacts.

You say where the data lives, cadence, Gold shape, and regulation (SOX, GDPR, HIPAA…).

Agents produce config, PySpark, quality gates, star schema or rollups, Step Functions, Terraform, tests.

You approve and commit. CI/CD promotes. Same scripts in QA / Staging / Prod.

Fit

Drops into the AWS and CI/CD you already have

  • Services: S3, Glue, Athena, Iceberg, KMS, Lake Formation, Step Functions, EventBridge, SNS, CloudTrail
  • Promotion: GitHub Actions shown; same stages map to CodePipeline, GitLab, Azure DevOps
  • Auth: OIDC to a least-privilege role — no long-lived keys in CI
  • Landing zone: catalog account vs consumer account is a parameterized split, not a rewrite
  • Security: agents have no prod credentials; Bronze immutable; zone-scoped KMS; PII masking as policy
