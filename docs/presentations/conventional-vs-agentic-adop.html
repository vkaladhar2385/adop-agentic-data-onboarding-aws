Conventional automation vs
agentic pipeline creation

Same AWS runtime can power both approaches.
The difference is how you produce governed, repeatable pipelines — and who owns the rules.

ConventionalEngineer writes Glue, Terraform, and orchestration directly — one bespoke project per source.
Agentic ADOPHuman states rules once → agents emit specs → codegen renders → CI + verifier prove deploy.

One sentence: Conventional automates the pipeline; ADOP automates the creation of governed, repeatable pipelines.

Conventional path

How most teams build E2E pipelines today

Analyst / DE asks questions → Engineer writes Glue or Airflow scripts → Engineer writes Terraform / CloudFormation → Manual testing in sandbox → Deploy (terraform apply + ad-hoc console) → Hope documentation still matches production

What works

  • Mature platform teams with strong templates and code review
  • Full control — no agent or MCP layer to learn
  • Proven at scale when discipline is high

What breaks down

  • Business rules live inside PySpark — hard to audit
  • Each new source ≈ copy-paste mini-project
  • PII, quality gates, and catalog drift across workloads
Source of truth: Python, SQL, Terraform files2 / 9
Agentic ADOP path

A governed multi-agent factory

Human: PII, dedup, thresholds, schedule, compliance → Phase 1 discovery gate (no codegen until answered) → Dedup + profile sample data → Sub-agents build specs only (no MCP, no deploy) → render_workload.py → deterministic scripts + SFN/DAG → pytest + schema validators + codegen drift CI → Human approves deploy → MCP-first catalog / LF / IAM + Terraform compute → Post-deploy verifier (deploy not done until green)

Agents do not freestyle production PySpark. They emit YAML specs; templates render code with spec_hash headers; hooks block hand-edits.

Guardrails (Tier A + B)

  • Write guard — blocks direct edits to generated scripts
  • Cedar policies — sub-agents cannot call MCP
  • AgentOutput schema — structured handoffs between stations
  • CI drift check — spec and artifact must match

  • Default: Step Functions + EventBridge (cost guardrail)

Official ADOP is the blueprint. This repo is a production-minded fork — same agentic philosophy, different default plumbing.

Benefits

Why invest in the agentic factory?

1 · Governance by constructionDiscovery gate blocks build until PII, thresholds, and schedule are explicit — not discovered in prod.
2 · Repeatable SKUWorkload #4 and #5 use the same stations as #1; marginal cost per source drops.
3 · Compliance artifactssemantic.yaml, LF-Tags, quarantine, verifier checks — easier to show auditors than reverse-engineering PySpark.
4 · Platform evolutionChange one Jinja template or Glue default → re-render all workloads; no N manual edits.

AgentCore / Bedrock (Tier B) hosts MCP tools in the cloud — agents call AWS through a governed Gateway, not scattered CLI scripts.

Honest trade-offs

Agentic is not “free magic”

CostReality
Upfront factory buildSpecs, templates, MCP, hooks, tests — significant initial investment (Tier A + B)
Process rigorDiscovery questions feel slower than “just write the script”
More moving partsGateway, LF, IAM, codegen drift — vs a single Terraform module
Humans still requiredAgents enforce that stewards were consulted; they don’t replace them
Same AWS billEnd state is still Glue + Iceberg + orchestrator — you industrialize configuration

Best fit: teams onboarding many sources under SOX / GDPR / HIPAA with a need for repeatable governance, not one-off ETL scripts.

Not a replacement for strong platform engineering — an accelerator on top8 / 9
